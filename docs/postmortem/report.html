1. Executive summary

Delivery speed was never the constraint. Phases 0-4, planned as 28 weeks, closed in 9 calendar days on 2026-10-24, with a heavily scripted restructure, a verification gate at every step and unusually candid "not verified" notes. What limited the project was everything around the code: usage, owner-held decisions and checks, and test isolation. On day 2 the development context reached about 455k tokens and work stopped for about 90 hours under the owner's weekly usage threshold. Phase 5 has since idled for most of a week on four owner items, the Game Mode fix is still unverified on real hardware, and the fork has fallen 13 stable upstream releases behind.

The main causes are process defaults that arrived late or not at all. Work units, handoffs and pacing were adopted as a fix on day 2 rather than as the starting setup. Desktop UI walks ran in the owner's live session until the Phase 5 VM lab, which sent the owner's installed-app list to Google's Play Store lookup and changed real settings. Owner questions and hardware checks were recorded in files and batched at step or phase ends, with no alert. No cadence was ever set for merging upstream releases. The planning session added its own errors: the first plan borrowed another project's design, and its week-based schedule never matched agent-driven delivery.

What to change: make GUI tests refuse to run against the owner's real session; merge each upstream release within a week and report the lag daily; push a phone notification when the pacer waits on the owner; attach a short hardware checklist to every alpha; and fold the unit/handoff/pacing scheme into the Token Usage Standard as the default for multi-day projects.

3. Method

  1. Evidence. Claude Code transcripts, git history, the plan, the usage and lab records, and the session journal (the only record of Cowork sessions) were mined with postmortem.mjs mine into 3 machine signals.
  2. Analysis. The work was reviewed through nine lenses: Process efficiency, Logic & correctness, Planning & scope, Token & usage, Tooling & automation, Environment & lab, Communication & handoffs, Quality & testing, Standards & ai-assets.
  3. Audit. Every observation was handed, with its evidence but not its conclusion, to an auditor who tried to disprove it. Verdicts: confirmed (evidence holds, confidence ≥ 70), plausible (supported but not proven), rejected (disproved or unsupported; listed in Appendix A). Self-audits are capped at confidence 70.
  4. Evaluation. Every recommendation states benefit and effort (1–5), risks, the alternatives considered and why this option was chosen. Score = severity × benefit × (confidence ÷ 100) ÷ effort.
  5. Completeness. Every machine signal is tied to a finding or explicitly dismissed with a reason (Appendix B). The report cannot be generated otherwise.

Notes and limits

Interim review: Phase 5 is in progress (pacer waiting-owner since 2026-11-05). Run from claude.ai (Cowork-style surface) linked to the owner's computer. The Claude Code transcripts in ~/.claude on the owner's machine are a protected location and could not be read, so there are no token, tool-call or interrupt metrics for the Claude Code sessions; the only mined transcript is the 2026-10-16 claude.ai planning session (truncated before this review began). Git metrics come from the GitHub copy of main (through 2026-10-24, since the push rule allows pushes only at a phase close); the 27 unpushed Phase 5 commits through 2026-11-05 were read from the local git reflog. The git churn figures include upstream's own commits merged on 2026-10-16. The plan lives in PORT_PLAN.md, which the miner does not parse (it reads docs/PLAN.md), so plan progress was taken from PORT_PLAN.md, the handoffs and DEVLOG by hand. There is no session journal; Claude Code sessions were reconstructed from the 410 KB DEVLOG (read in four parts by subagents), the per-phase handoffs, gotchas.md and the reflog. Each observation was audited by an independent reviewer subagent (opus for severity 4 and logic findings, sonnet otherwise) given the claim and evidence references only; reviewers corrected numbers in 11 observations and rejected two.
